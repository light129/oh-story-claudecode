# Agent Note: 开书按作者确认点分段加载，重的一段换新上下文

Status: proposed
Date: 2026-09-26
Related: [35K 加载上限](../../implemented/architecture/2026-09-26-per-call-load-ceiling-35k.md)

## Problem

开书在同一会话里连续做选题、核心设定、卷纲、首批细纲，有时还接着写第 1 章。每一步的流程说明、模板和技法参考都留在上下文里：规则部分约 34–56K（workflow-setup 12K、artifact-protocols 9K、project-files 5K，加上排纲技法 outline-structure-theory 8K、情绪方法 4K、读者契约 4K、开篇设计 5K），35K 上限只能先把它列为豁免。

按作者的时间线看，开书是一串作者要确认的时刻：定方向 → 定设定 → 看卷纲 → 看首批细纲 → 看第 1 章。后一时刻真正依赖前一时刻的只有落盘文件（题材定位、设定、卷纲、细纲），不依赖前一时刻的操作说明；而对话里作者口头定下的事如果没落盘，换了上下文就会丢。

## Proposal

- **按时刻拆流程文件**：`workflow-setup.md` 只留定方向与定设定（对话为主，模板随用）；卷纲一段拆成 `workflow-volume.md`（全书体量、卷级大纲、对标节奏回流、排纲自查 1–4、卷纲产物与汇报）；细纲一段拆成 `workflow-outline.md`（批次步骤、细纲模板、供给自查、补纲流程、设定补全、缺口三级、汇报）。每个时刻进入时才读自己的文件与技法，技法按该时刻的问题读（卷纲读情绪方法与契约，细纲读开篇设计与按剧情批），不整读 outline-structure-theory。
- **交接只靠落盘**：每个确认点先把作者口头定下的事写进 `设定/题材定位.md`（或作者记忆），再往下走；下一时刻的上下文只读文件。
- **重的时刻换上下文**：有子代理的端，卷纲与每批细纲由 story-architect 在新上下文里做，主会话只和作者对话、收结果、汇报；story-architect 按任务读取表只读该时刻需要的文件（时刻文件经 shared-references 同步到 agent-references）。没有子代理的端，在确认点的汇报里建议作者新开对话接着做，并说明理由；不强制。
- **预算**：按时刻登记路径（主会话定方向与设定、story-architect 出卷纲、story-architect 出一批细纲、solo 各时刻），每条及分支 ≤35K；取消开书豁免。

## Alternatives considered

- **保持主会话一口气做完，只删文字**：最强理由是不改变谁来写大纲，风险最小。否：累计的主要是按时刻本该分开的说明与技法，删到 35K 要砍掉排纲技法本身。
- **默认由 story-architect 包办整个开书**：最强理由是主会话最轻。否：定方向、定设定是和作者来回讨论的过程，交给子代理作者就插不上话。
- **只拆文件不换上下文**：最强理由是改动面小。否：同一会话里读过的文件不会离开上下文，拆开后累计总量不变。

## Validation plan

与现行 v0.8.1 对照，同一题材前提、同一组作者回答，两种流程各产出卷纲与首批细纲（两本新书）：细纲契约检查通过率、目标情绪与主角目标具体度、异家族或匿名评委的卷纲/细纲配对盲评、据细纲写第 1 章后的配对盲评。门槛在数据产生前冻结。

## Consequences

- 收益：开书每次调用 ≤35K；每一时刻只看该时刻的规则，作者口头决定强制落盘。
- 代价：卷纲与细纲在有子代理的端改由 story-architect 产出，大纲风格可能变化，需要实测；主会话汇报要读子代理产物；solo 端若作者不换对话，累计仍会超出。
